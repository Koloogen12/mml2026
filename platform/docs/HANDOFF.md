## 2. Чат: работает через прокси владельца

**Состояние: живой.** Проверено: `POST /api/v1/chat` → 200, стрим идёт, ответ
по-русски за ~3 с, ноль ошибок в логах за час.

Механика: `ANTHROPIC_BASE_URL=https://ai.makemelook.tech` — Cloudflare Worker
`mml-ai-proxy` (аккаунт владельца). Настоящий ключ Anthropic живёт в воркере,
бэкенд аутентифицируется у него через `ANTHROPIC_PROXY_KEY`. Код поддерживает
это давно (`config.go`: пустой `ANTHROPIC_BASE_URL` = прямой Anthropic, для дева).
Обе переменные прокидываются в `docker-compose.prod.yml` (строки 70–71) —
серверный и репозиторный файлы совпадают, деплой их не ломает.

**Почему чат лежал раньше:** переменных не было в `/opt/mml-platform/.env.prod`
нового стека → `${ANTHROPIC_BASE_URL:-}` → пусто → прямой `api.anthropic.com` →
**403** (сервер в Москве, Anthropic Россию не обслуживает). Прямой запрос с
сервера даёт 403 и сейчас — работает именно прокси.

**Что важно знать новой сессии:**

- Прокси — обход гео-ограничения Anthropic. Ограничение юрисдикционное, поэтому
  риск — блокировка аккаунта, а не деградация. Это осознанное решение владельца;
  он ушёл решать инкорпорацию за рубежом, после чего прокси можно снять.
- Ассистент (я) **отказался строить такой прокси** и не берётся его развивать
  или чинить. Это не мешает работать с чатом как с фичей: транспорт — инфра
  владельца, она уже поднята.
- Если чат вдруг отдаёт 403 — первое, что проверить: доехали ли
  `ANTHROPIC_BASE_URL` и `ANTHROPIC_PROXY_KEY` до контейнера
  (`docker exec mmlplat-backend-1 env | grep ANTHROPIC`). Именно этого и не
  хватало.
- Стиль-код (`/passport/style-code`) генерируется Claude — с живым чатом он тоже
  должен собираться. **Не перепроверено**, стоит проверить в новой сессии.

**Проверено и годится как запасной путь без прокси:** с прод-сервера напрямую
отвечают `api.deepseek.com` и Qwen (Alibaba, международный) — **401 (нужен
ключ)**, а не 403; РФ они не запрещают. DeepSeek показал рабочий tool-calling с
русским запросом. GigaChat/YandexGPT владелец отклонил по качеству.

## 3. Как деплоить (и как я на этом обжигался)

```bash
cd platform
rsync -az --exclude='.env*' --exclude='node_modules' --exclude='dist' \
  backend/ root@135.106.146.200:/opt/mml-platform/backend/
rsync -az --exclude='.env*' --exclude='node_modules' --exclude='dist' \
  web/ root@135.106.146.200:/opt/mml-platform/web/
ssh root@135.106.146.200 'cd /opt/mml-platform && \
  docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build backend web'
```

**Три правила, оплаченные потерянным временем:**

1. **Проверять тем, чем собирается прод.** `tsc --noEmit` даёт ЛОЖНЫЙ зелёный —
   он берёт другой конфиг. Прод собирает `tsc -b && vite build`. Проверяй:
   `pnpm --filter @mml/buyer build`.
2. **После деплоя сверять бандл, а не код 200.** Сборка может упасть, контейнер
   продолжит крутить старый бандл, а `/app/` честно ответит 200. Я так дважды
   рапортовал успех при неработающем деплое:
   ```bash
   js=$(curl -s https://makemelook.ai/app/ | grep -oE '/app/assets/index-[A-Za-z0-9_-]+\.js' | head -1)
   curl -s "https://makemelook.ai$js" | grep -c "искомая-строка-из-правки"
   ```
3. **`--env-file .env.prod` обязателен.** Без него compose берёт имя проекта из
   папки и поднимает ВТОРОЙ стек со своими томами рядом с живым (уже случалось,
   разгребали). Имя прибито в самом compose (`name: mmlplat`), но привычка нужна.

Секреты только в `/opt/mml-platform/.env.prod` на сервере, в git их нет.

## 4. Проверки, которые обязаны проходить

```bash
cd platform/web && pnpm --filter @mml/buyer build   # tsc -b + vite
cd platform/web && pnpm exec eslint apps/*/src      # rules-of-hooks = ошибка
cd platform/backend && go build ./... && go test ./internal/...
```

**CI нет.** Это главная организационная дыра: все три проверки запускаются
руками, поэтому ошибки ловил владелец, а не я. Поднять — приоритет.

Линтер добавлен после того, как условный хук (объявленный под ранним `return`)
уронил всё приложение в белый экран. TypeScript такое не видит. Линтер за одну
сессию нашёл ещё два обращения к переменным до объявления.

## 5. Грабли, на которые я наступил (не повторять)

**Данные, зависящие от пола, — только в `web/apps/buyer/src/wardrobe.ts`.**
Копии разъехались по трём файлам, каждая осталась женской: мужчинам предлагали
обувь 36–39, верх 42/S, бюджет на «Платья», стоп-лист с пайетками и мини.
Чинилось по одному месту и снова разъезжалось.

**Ключ и его данные держать вместе.** Подписи бюджета лежали отдельно от сумм;
я дал мужчинам ключ `top`, суммы про него не знали → `undefined.length` → падал
весь кабинет. Теперь `BudgetRow` несёт ключ + подпись + шкалу.

**Паспорт: только `SavePatch`, не `Save`.** `Save` вставляет ПОЛНУЮ версию
(SCD-2). Частичное сохранение через него стирало всё остальное: подписка на
бренд снесла пол, стили и размеры реальному пользователю. Слияние покрыто
тестами (`mergePrefs`), они падают на старом поведении — проверено.

**Инлайновые шорткаты бьют CSS.** `background:` сбрасывает `background-size`,
`animation:` — `animation-play-state`. Оба раза мой фикс молча не работал.

**`backdrop-filter` пересчитывается при любой перерисовке внутри своего
элемента.** Размытие обязано жить отдельным неизменным слоем под контентом
(`.dp-scrim-blur`), иначе ховер на кнопке мигает всем экраном.

**Проверять сценарий, а не экран.** Вход ломался на переходе гость→вошедший,
а я проверял уже вошедшего.

## 7. Что дальше — по приоритету

1. **CI** (Прод-4). Без него ошибки ловит владелец. Прогон: три команды из §4.
2. **Стиль-код.** Чат жив → должен собираться. Запросов к `/passport/style-code`
   после включения прокси в логах ещё не было — проверить, зайдя в паспорт.
3. **Нормализация пакшотов.** Фото в каталоге пяти пропорций: Farfetch 0.75,
   NOCONCEPT 0.667, Brûler 0.79–0.8. В коробке 3:4 с `contain` они вписываются
   по-разному — владелец видит это как «фотки скачут». CSS это не лечит:
   нужно приводить к одному холсту на приёме фида (ETL + MinIO уже есть).
   ~2 часа, одноразово, дальше работает на всех партнёров.
4. **Прод-4 остальное**: rate-limit шире, мониторинг, бэкапы, ротация ключей.
   Ключи (OAuth, Resend) владелец решил не ротировать до релиза.
5. **Прод-5**: реальная примерка — координируемый релиз виджета.

**Открытые мелочи:** письма уходят с `@makemelook.tech`, а сайт `makemelook.ai`
— несоответствие домена в отправителе, чинится верификацией .ai в Resend.
Восемь мест с `set-state-in-effect` (лишние перерисовки, не падения) —
предупреждения линтера, разгрести отдельно.

## 8. Как работать с владельцем

Данил — основатель, ждёт партнёрства уровня CTO, пишет по-русски.

Стандарт, который он задал: **«либо делаем по-настоящему, либо честно говорим,
что этого пока нет»**. Выдуманные данные в интерфейсе — худшее, что можно
сделать; за сессию их вычищено много (фейковые партнёры на лендинге, моковые
цвета, несуществующие приложения в футере).

Он проверяет руками и находит то, что пропущено. Не рапортовать успех по
косвенным признакам — сверять факт (§3, правило 2).
