# QA-отчёт MakeMeLook — сквозной прогон (buyer / merchant / admin)

Дата: 2026-07-16. Метод: 3 QA-аудитора (код + curl по бэкенду) + живой прогон в браузере.
Стек: backend :8090, reco :8091 — оба здоровы. Все данные ниже проверены на реальном бэке.

**Легенда статусов:** OK — работает · DEAD — кнопка/ссылка без обработчика · MOCK — захардкоженные данные вместо API · TODO — заявленная незавершёнка/честное пустое · BUG — реальный дефект.

**Главный вывод:** проводка бэкенда **целиком боевая** во всех трёх приложениях (auth, чат SSE, примерка-гейт 152-ФЗ, паспорт, CPA, все 18 admin-эндпоинтов, партнёрские). Проблемы — на ФРОНТЕ: мёртвые кнопки (1:1-перенос макетов без проводки), demo-контент и несколько реальных багов честности/логики.

## ✅ ИСПРАВЛЕНО (QA-сессия 2026-07-16)

**Явные правки Данила:** Home-блок → «Ещё для вас»; «Похожее»/«С этим носят» по гардеробным зонам; Apple-вход убран (Google+Яндекс); 152-ФЗ модалка убрана (гейт снят и на бэке — согласие у виджета).

**Батч A (честность):** приветствие по реальному времени (не «Катя»); избранное пустое (не сид 6 товаров); тост «+Новая»; фейк kill-switch (Lamoda/вейтлист) убраны; Users-паспорт реальный API; «12 STOREEZ»→«Ваш бренд»; визард показывает ошибку при фейле; реальный logout партнёра (эндпоинт + чистка сессии/cookie).

**Батч B:** ✅ партнёрский синк каталога end-to-end («Проверить фид» реально импортирует → реальные счётчики → товары в кабинете); ✅ админ «Запустить синк» подключён (POST /admin/partners/{id}/sync).

**Батч C (начато):** партнёрский вход — только email-код (пароль/восстановление/«Демо:» подписи убраны).

### Осталось (для решения по приоритету)
- **Оценка ИИ в Desk / Rate** — завязаны на demo-пары «запрос→выдача» (реальных пар нет) → осмысленно только вместе с реальным источником пар (отдельная фича).
- **~30 «мёртвых» кнопок** — в основном НЕвстроенные фичи, требующие бэкенда: загрузка лого/размерной сетки, выгрузка данных 152-ФЗ (Users), bulk-действия товаров (скрыть/пересобрать), «повторить» примерку, тумблеры уведомлений, «остановить/пауза» партнёра, «скачать превью». Стратегия на выбор: (а) **скрыть** невстроенное (UI показывает только рабочее) — быстро и честно; (б) **строить по фиче** — долго. Чисто косметические (соцсети/футер-ссылки маркетинга, App Store/RuStore, стрелки фото) — скрыть.

## 🔴 РЕАЛЬНЫЕ БАГИ (выявлены; часть исправлена выше)

### Buyer
1. **Гонка consent→tryon.** `confirmConsent` вызывает `logConsent` без `await`, сразу `beginProcessing()`→`runRealTryOn()` → первая реальная примерка может уйти на бэк раньше записи согласия (403). `appStore.ts:283-287`.
2. **Согласие не переживает перезагрузку.** `consentGiven` — только клиентский стейт; после reload гейт 152-ФЗ появляется снова, хотя согласие в БД (фронт не читает `/consents`, чтобы удовлетворить гейт).
3. **Сид избранного.** Новый/гостевой юзер получает 6 «избранных», которые не выбирал — `favIds` сидится первыми 6 товарами каталога. `appStore.ts:150`.
4. **Copy-paste баг тоста.** Favorites «+ Новая коллекция» → тост «Ссылка на паспорт скопирована». `Favorites.tsx:66`.
5. **«Текст согласия» — мёртвый span** в consent-модалке (юр-ссылка не работает). → навести на `/legal/privacy.html`.
6. **Consent-модалку нельзя закрыть/отменить** — нет ×/Отмена, Escape и клик по фону не работают.
7. **Фейковая персонализация (честность):** приветствие «Катя» захардкожено; обоснование стилиста «…в бюджете и размере 44» (`Chat.tsx:42`, `ProductDetail.tsx:149`) — статично, не из паспорта.
8. **Мёртвые OAuth** Google/Apple (×4) в онбординге и Auth-модалке.

### Admin
9. **Users A2: паспорт — МОК** (`PASSPORT` из shared.ts), хотя есть боевой `GET /users/{id}/passport` (как в Desk). Всем показывается один фейковый паспорт. `Users.tsx:5,281`.
10. **«Запустить синк» — мёртвая** (`Partners.tsx:266`) при живом `POST /sources/{id}/sync`. Ключевое партнёрское действие недоступно из UI.
11. **Инлайн-оценка ИИ в столе стилиста (👍/👎 + «Почему») никуда не уходит** — только локальный `setRatings`. gold-set из Desk не собирается. `Desk.tsx:799-826`.
12. **2 фейковых kill-switch тумблера** (Lamoda-пауза, приём в вейтлист) — локальный `useState`, продукт не меняют. Опасно: оператор думает, что поставил партнёра на паузу. `Flags.tsx:25-26,50-63`.
13. **POST /labels без привязки** к паре/сессии (пара — мок) → gold-set засоряется пустыми строками. `Rate.tsx:65`.
14. **Бэк-минор:** `POST /admin/sources/{id}/sync` не валидирует существование источника (999 → 202).

### Merchant (партнёр)
15. **Синк каталога не доходит до товаров.** «Проверить фид» лишь регистрирует источник (`status:pending`); фонового парсинга/импорта из кабинета нет → `GET /products` вечно `[]` → `connected` никогда не true → весь «подключённый» кабинет недостижим. **Главный партнёрский сценарий разорван.** `Cabinet.tsx:105,228`.
16. **Панель успеха визарда — фикция.** «Импортировали 1 240 из 1 305 / 980 пригодны / 65 не прошли» захардкожено и показывается ВСЕГДА, даже при ошибке (`r.ok ? "success" : "success"`). Партнёр видит успех, которого не было. `Cabinet.tsx:236`.
17. **Новый партнёр видит чужой бренд «12 STOREEZ»** — fallback при пустом brand_name во всех заголовках/аватарах/витрине. Нарушает честный пустой стейт. `Cabinet.tsx:104`.
18. **«Выйти» не разлогинивает** (все 3 кнопки) — только переключают view, `accessToken`/refresh-cookie остаются валидны, logout не зовётся. `Cabinet.tsx:295,747`.
19. **Пароль/Яндекс ID/восстановление — фейк** (партнёрский бэк = только email-код): `signinGo`/`google`=`finish()` входят без бэка; recover/reset ничего не шлют; в проде видны подписи «Демо: любой пароль…». Убрать. `Apply.tsx:139,163,288`.
20. **preview-product 502 на крупных RU-магазинах** (lamoda/wildberries/ozon блокируют серверный fetch) — герой падает на реальных партнёрских URL. Нужен headless/прокси или ручной ввод-фолбэк. `preview.go`.
21. **Расписание синка не уходит в бэк** (`connectSource` шлёт только kind+url); загрузка лого/размерной сетки/«скачать превью» — тосты без файла; настройки Компания/Контакт uncontrolled и не сохраняются. `Cabinet.tsx:232,687,695,738`.
