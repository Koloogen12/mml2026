### Извлечённые константы

**Цветовая палитра (наблюдаемая):**

| Роль | Цвет | Где используется в KP |
|---|---|---|
| Основной фон | `#FFFFFF` белый | все страницы |
| Акцент / бренд | `#3B82F6` яркий синий (tailwind `blue-500`) | wordmark «MakeMeLook.ai» в левом верхнем углу каждой страницы, разделители под заголовками, пре-заголовки uppercase («КОММЕРЧЕСКОЕ ПРЕДЛОЖЕНИЕ», «ПРОБЛЕМА», «РЕШЕНИЕ»), метрики в карточках |
| Основной текст | `#000000` / near-black | заголовки H1, тело текста |
| Серый для second-tier текста | `#6B7280` / `#9CA3AF` | подписи, вспомогательный текст |
| Акцент боли (редко) | red/pink | буллеты проблем |
| Акцент позитивных метрик | green (ограниченно) | «10 000%+ ROI», «Экономия от 80%» |

**Типографика:**
- Сан-сериф Inter / SF Pro / близкий по характеру — чистый, geometric, без засечек.
- Иерархия через размер и вес: H1 bold ~40-48px, H2 semibold ~24-28px, тело 14-16px regular.
- Uppercase tracking для пре-заголовков (типа `tracking: 0.08em`).
- Никаких декоративных/display-шрифтов. Никаких засечек (serif) в KP.

**Композиция:**
- Широкое «дыхание» — много воздуха вокруг блоков.
- Левая привязка вордмарка сверху → читается как Stripe / Linear / Notion.
- Карточки с метриками: мягкие скругления (borderRadius ~8-12px), тонкий border или light background `#F5F5F5`.
- Разделители — тонкие синие линии, 2-3px, короткие (не на всю ширину).

**Логотип:**
- Текстовый wordmark «MakeMeLook.ai» синим цветом, без символа.
- Вес полужирный (semibold/bold).
- На белом фоне всегда.

### Вердикт: что это за дизайн-ДНК

MakeMeLook уже — **чистая B2B SaaS айдентика в школе Stripe / Linear / Notion**, с лёгким fashion-призвуком (через спек Lovable упомянут Farfetch). Это НЕ fashion-editorial школа (тёплые нейтралы, serif, film grain), это НЕ burgundy-premium школа (как я ошибочно предложил). Это — **яркий синий акцент на белом**, инженерная чистота, геометрические sans-serif.

**Что это даёт нам стратегически:** MakeMeLook позиционируется не как модный бренд, а как *инженерное решение для фэшн-индустрии*. Это правильно для B2B — CMO покупают у инженеров доверие, а у стилистов — вдохновение. Мы продаём доверие.

**Что это ограничивает:** нужно аккуратнее с «editorial wow» режимом каруселей. Visual wow в нашем случае = демонстрация технологии (try-on slider, 5-слойная примерка), а не художественная съёмка одежды.

## Часть 3. Три направления moodboard (выбор)

Все три направления **строятся на существующей айдентике MakeMeLook** (синий #3B82F6 + белый + Inter + clean B2B SaaS). Отличаются тем, **как эта база эволюционирует для Instagram**, где визуальная плотность и wow-эффект важнее, чем для PDF-КП.

---

### Направление A — «Continuation» (прямое продолжение текущей айдентики)

**Концепт:** Instagram = тот же KP, просто в формате 1080×1350. Максимальная консистентность, минимум сюрпризов. Клиент увидит пост → кликнет на сайт → увидит тот же язык.

**Палитра:**
- Основа: белый `#FFFFFF`, near-black `#0A0A0A`, синий акцент `#3B82F6`
- Tertiary grey `#6B7280` для second-tier текста
- Светлый фон карточек `#F5F7FA`

**Типографика:**
- Inter (latin + cyrillic, есть в Google Fonts)
- H1 bold 48pt, H2 semibold 28pt, body 16pt regular, pre-headers uppercase 12pt + tracking

**Логика слайда:**
- Большой белый воздух — 100px margins минимум
- Типографика-first. Визуал — иллюстрация к тезису, а не герой
- Crisp white bg всегда, никаких градиентов
- Синий — только акцент (цифры, divider, CTA button, pre-header)

**Плюсы:**
- Минимум работы — всё уже есть в KP
- Максимальная консистентность бренда
- Быстро запускаемся — можем начать на следующей неделе

**Минусы:**
- Рискует выглядеть «скучно» на фоне fashion-editorial конкурентов
- Не несёт «wow» — будет сложнее выбить viral-охват
- Для fashion-индустрии может читаться как «не свой» (слишком tech)

**Кому подходит:** если приоритет — цикл продажи, а не охват. Лид пришёл по таргету → увидел профиль → понял «это серьёзно» → запросил демо.

---

### Направление B — «Premium extension» (айдентика + fashion-editorial слой)

**Концепт:** сохраняем ядро (синий + Inter + чистота), но добавляем **второй слой** визуальной теплоты для тех постов, которые должны выглядеть «fashion», а не «SaaS». Например: карусели с кейсами (свадебные платья) — editorial-стиль; технические карусели — текущий clean SaaS.

**Палитра:**
- Primary (как было): белый `#FFFFFF`, black `#0A0A0A`, blue `#3B82F6`
- + Secondary warm neutrals: бежевый `#F4F1EC`, тёплый off-white `#FAF8F3`, мягкий charcoal `#2A2A2A`
- Blue используется как акцент, а не доминанта — даёт ощущение «свой в fashion»

**Типографика:**
- Inter — для tech/data постов (MOFU/BOFU, метрики, продукт)
- + Дополнительный serif (напр., **Fraunces** или **Recoleta**, обе есть в cyrillic) — для кейсов и fashion-storytelling постов, в H1

**Логика слайда:**
- Два визуальных режима:
  - **SaaS mode** (технические посты): белый фон + Inter + синий акцент → как Direction A
  - **Editorial mode** (кейсы, fashion): тёплый off-white + serif H1 + maroon/warm accent вместо яркого синего → как COS / Aesop
- Чёткое правило: тип контента определяет режим (матрица в visual-code.md)

**Плюсы:**
- Гибкость — один tool of для сухой аналитики, другой для fashion-storytelling
- Читается как «свой» и у CMO fashion-ритейла, и у инженеров
- Больше шансов на viral-охват через editorial-посты

**Минусы:**
- Сложнее поддерживать (две системы параллельно)
- Нужно обучить редактора / агентство, когда какой режим
- Первые 10 постов — сложнее генерить (надо фиксировать обе подсистемы)

**Кому подходит:** если приоритет — и охват, и цикл продажи. Готов вложить больше времени в настройку системы.

---

### Направление C — «Demo-first wow» (визуал продукта — герой, типографика — сервис)

**Концепт:** главная валюта MakeMeLook — **визуал технологии** (5-слойная примерка, try-on до/после, slider). Делаем это центральным визуальным языком IG. Типографика отходит на второй план — она сервисная, помогает читать визуал.

**Палитра:**
- Primary: белый `#FFFFFF`, black `#0A0A0A`, blue `#3B82F6`
- + Saturated accent для call-outs: hot pink `#FF3B7D` или electric orange `#FF6B35` — на метках «NEW», разделителях, CTA button
- Больше насыщенности, меньше «calm» — школа Zero10 / Runway

**Типографика:**
- Inter везде, минимум декораций
- Текст — подписи к визуалу, не герой. Max 2 строки на слайде
- Крупные цифры — только если они связаны с визуалом (напр., «5» слоёв — рядом с визуалом 5 слоёв)

**Логика слайда:**
- **Визуал занимает 70%+ слайда.** Типографика — layer поверх/под
- Использование slider-эффекта в каруселях (слайд 1 = до, слайд 2 = после, с общим анкером)
- Много try-on screenshots, 3D-рендеров, before/after
- Короткие демо-reels с ползунком — main content format

**Плюсы:**
- Максимальный wow-эффект и viral-потенциал
- Визуально отличается от конкурентов (они — или скучные SaaS, или slick 3D без продукта)
- Сильный instagram-native формат

**Минусы:**
- Требует постоянной генерации качественных product shots (Nano Banana + Seedance — критичны)
- Риск: выглядит слишком «марком» для enterprise-покупки (CMO может подумать «это для маркетплейса, не для нашего бренда»)
- Меньше места для TOFU-индустриальных постов (провокации / data)

**Кому подходит:** если главная цель — виральность, узнавание бренда, инбаунд из холодной аудитории. Цикл продажи поддерживается через DM и демо-ссылку в bio.

## Часть 4. Рекомендация и следующий шаг

**Моя рекомендация — Направление B («Premium extension»).**

Причины:
1. ICP-гибрид: CMO fashion-ритейла (нужен editorial) + технические стейкхолдеры (нужен clean SaaS) — один режим не покрывает обоих.
2. Воронка 60/30/10: TOFU-контент (60%) — это провокации и industry data, где SaaS-режим естественен. MOFU/BOFU (40%) — это кейсы и демо, где editorial-слой добавляет доверия к «мы умеем работать с fashion».
3. Не ломаем существующую айдентику — она остаётся основой. Просто добавляем *слой* для editorial-контента.
4. Даёт гибкость: если через 2 месяца мы увидим, что editorial-режим не работает → откатываемся к Direction A без пересобирания всего.

**Риски рекомендации:**
- Сложнее в первом квартале. Нужен чёткий decision tree «какой пост — какой режим».
- Потенциальный визуальный хаос, если не зафиксировать правила в `visual-code.md`.

**Что будет в `visual-code.md` после твоего выбора:**
1. Палитра (с примерами применения per режим).
2. Типографика (Google Fonts links, весы, размеры для IG 1080×1350).
3. Сетка слайда и safe zones.
4. Decision tree «какой тип контента = какой визуальный режим» (если B или C).
5. 5 эталонных промптов Nano Banana Pro (обложка, слайд-цифра, слайд-текст, слайд-визуал, финальный-CTA).
6. Эталонные фигурные примитивы (разделители, плашки, callout-блоки).

**После выбора направления — за 1 сессию:**
- Финализирую `visual-code.md` (2-3 часа работы).
- Разморожу промпты в `01_manifest.md` под новый визуальный код (30 мин).
- Напишу промпт для аватара профиля (15 мин).
- Напишу 5 промптов для обложек хайлайтов (30 мин).
- Напишу промпты для 2-го и 3-го пина (карусели «Кейс свадебного платья» и «ROI-калькулятор») — 2-3 часа.
