В репозитории уже есть рабочие части, которые переиспользуем напрямую. Это меняет оценку: критический путь до демо — недели, а не месяцы.

## 1. Целевой стек (зафиксировать)

- **Backend:** расширяем существующий Go-монолит `mml-saas-backend` новыми модулями (модульный монолит, отслаиваем сервисы позже). Postgres + **pgvector**, MinIO, Gemini через genai.
- **Инференс (эмбеддинги/реранк):** Python-сайдкар (FashionCLIP + reranker). На старте эмбеддинги можно считать пакетно; горячий путь — только ANN-поиск в pgvector.
- **Frontend (чат-PWA):** новый пакет `chat-web` — React 19 + Vite + Zustand + Tailwind v4 (как в widget-tryon). Mobile-first, PWA (manifest, service worker, offline-состояние).
- **iOS:** фаза A — PWA. Фаза B — обёртка Capacitor или нативное приложение (решение по iOS ниже). Дизайн уже iOS-native по ощущению.
- **LLM:** провайдер-абстракция с failover: прокси к Gemini/OpenAI (Cloudflare Worker) + локальный fallback GigaChat/YandexGPT. Эмбеддинги — self-hosted.
- **CPA:** сервис редиректов `/r/` с подписанным `click_id` + вебхук S2S-postback от партнёрских сетей.

## 2. Эпики и последовательность

Критический путь до демонстрируемой петли «чат → примерка → редирект»: **E1 → E2 → E3 → E4**. Остальное следом.

### E0 · Фундамент (до фичей)
- Решения из раздела 4 закрыты (имя, источник каталога, CPA-сеть, iOS, LLM).
- Новый пакет `chat-web`, монорепо-структура, CI/CD, окружения (dev/stage/prod), секреты.
- **Дизайн-система в код:** токены хендоффа → Tailwind config (цвета `--bg #F6F4EF`, `--ink #16150F`, `--accent #2743E3`), шрифты (Playfair Display / Golos Text / IBM Plex Mono), базовые компоненты (кнопки, карточка товара, пузыри чата, чипы, sheets, скелетоны, таб-бар).

### E1 · Каталог + ретривал (бэкбон — без товаров ничего не работает)
- **Ингест:** коннектор к первому источнику (маркетплейс-фид/партнёрская сеть) → нормализация в единую таксономию (категория, ткань, силуэт, цвет, размерная сетка, цена, наличие, deeplink).
- **LLM-обогащение:** извлекаем скрытые атрибуты (силуэт, вырез, «повод») через Gemini — переиспользуем genai.
- **Эмбеддинги:** FashionCLIP (фото+текст) → индекс в pgvector.
- **Retrieval API:** текст/фото-запрос → эмбеддинг → ANN → бизнес-фильтры (размер, наличие, цена) → кандидаты.

### E2 · Чат-ядро (поверхность продукта)
- **Оркестратор диалога:** разбор намерения (повод/бюджет/ограничения) → tool-calling (search / try-on / filters) → сборка ответа → **стриминг (SSE)**.
- **Фронт:** chat-home (5a/1b + таб-бар), диалог с дефолтом «Выбор стилиста» (1e) + карусель/сетка (1c/1d), Say More (1f), все состояния (стриминг, скелетон, no-results, ошибки).
- **Онбординг Style Passport до auth** (4a–4c), мёрж при регистрации. Auth (SMS/Apple/Google/VK) — расширяем существующий.

### E3 · Примерка + 152-ФЗ (дифференциатор)
- Оборачиваем существующий Gemini-движок в **очередь задач** + прогресс + оптимистичный UI + пуш по готовности (2c).
- **Consent-gate 152-ФЗ (2b):** версионированное хранение согласий {версия, дата, biometric, storePhoto}, раздельные непреселекченные чекбоксы, блокировка примерки без обязательного согласия, локализация данных в РФ, удаление биометрии в один тап.
- **Результат (2d)** + edge-кейсы (2e: плохое фото / ошибка генерации / товар распродан).

### E4 · Петля покупки + CPA (деньги)
- **Карточка товара (2a/4e)** с мультиретейлером и ценами.
- **CPA-редирект (3a):** сервис `/r/`, подписанный `click_id`, deeplink, интерстишл, обработка недоступности магазина.
- **Партнёрская сеть (Admitad/ePN):** subID, вебхук S2S-postback, сверка `click_id`, статусы конверсий (pending→approved→paid).
- Внутренние дашборды unit-экономики (доход на сессию/примерку/юзера).

### E5 · Коллекции + ЛК покупателя
- Коллекции/борды (3b/3c).
- **ЛК:** Паспорт стиля (4d, редактирование), история примерок, история кликов, **«Согласия и биометрия» с удалением данных**, настройки.
- Достроить TODO-экраны дизайна (ввод SMS-кода, шаги размеров/бюджета, история/согласия) — по существующим паттернам.

### E6 · Кабинет партнёра (B2B) — сначала дизайн, потом код
- Дизайна P1–P8 ещё нет — нужен отдельный проход в Claude Design.
- Реализация на базе `b2b-frontend` (Next.js): dashboard CPA, подключение каталога + Data Quality Score, аналитика/вкус-инсайты, выплаты, профиль бренда.

### Сквозное (параллельно)
Observability (логи/метрики/трейсы), пуши (web push VAPID + APNs), безопасность, антифрод по кликам, событийная шина + data platform (позже, когда пойдут данные для обучения реранкера), тёмная тема (фаза 2).

## 3. Порядок реализации фронта (по ходам хендоффа)

1. E0-компоненты (дизайн-система) → 2. Онбординг 4a–4c → 3. Home 5a/1b → 4. Диалог 1e/1c/1d + состояния 1f → 5. Карточка 2a/4e → 6. Consent 2b → 7. Примерка 2c → 8. Результат 2d/2e → 9. CPA 3a → 10. Коллекции 3b/3c → 11. ЛК 4d + TODO → 12. Пуши 5b, страница бренда 5c.

Каждый экран — со всеми состояниями (пустое / загрузка / успех / ошибка / офлайн / нужна авторизация / нужно согласие).

## 4. Развилки, которые надо закрыть до старта (блокеры)

| # | Решение | Почему блокер |
|---|---|---|
| B1 | **Первый источник каталога** (WB / Ozon / Lamoda / Yandex Market / прямые бренды) | Без товаров не стартует E1 — а это бэкбон. №1 приоритет. |
| B2 | **CPA-сеть и одобренные рекламодатели** (Admitad / ePN / прямые) | Определяет модель редиректа, postback и реальную монетизацию (E4). |
| B3 | **iOS-стратегия** (PWA-first → потом; Capacitor-обёртка; или нативно сразу) | Влияет на структуру фронта и найм. |
| B4 | **LLM-провайдер и бюджет** (Gemini/OpenAI через прокси vs GigaChat/YandexGPT) | Влияет на оркестратор, стоимость, гео-риски. |
| B5 | **Финальное имя/бренд** (или остаёмся MakeMeLook) | Домен, ассеты, юр-документы. |
| B6 | **Кто разрабатывает** (вы соло / штат / подрядчики) | Определяет гранулярность плана и параллелизм эпиков. |

## 5. Оценка (грубо, зависит от B6)

Для 1–2 сильных фуллстеков, при переиспользовании существующего:
- E0: ~1 неделя · E1: 2–3 нед · E2: 2–3 нед · E3: 1.5–2 нед (движок готов) · E4: 1.5–2 нед → **демо-петля ~8–11 недель.**
- E5: +2 нед · E6 (с дизайном): +3–4 нед.

Цифры ориентировочные; уточним после B6 и доступа к каталогу.
