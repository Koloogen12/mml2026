## 0. Bottom line

Мы строим **две связанные подсистемы**:
- **Passport model** — превращает вход пользователя (онбординг + опц. фото) в структурированный вектор «кто ты / что тебе идёт / что тебе нужно».
- **Rec model** — превращает `запрос + паспорт + контекст` в ранжированную выдачу товаров.

Ключ: **большая часть паспорта детерминирована и строится прямо сейчас, без каталога и LLM.** Retrieval/rerank блокируются каталогом (решение B1), но всё вокруг них — схема, правила, эмбеддинг-пайплайн, eval-харнесс — делаем параллельно. Строим **не с нуля**: расширяем `mml-saas-backend` (уже есть `product`, `consent_log`, `lead_try_on`, `avatar`, `diagnostic_result`).

**Что начинаем сегодня:** сервис инференса `mml-reco` + детерминированное ядро паспорта (тип фигуры, колорит→сезон) с тестами + миграции под pgvector и атрибуты.

## 1. Декомпозиция (что из чего состоит и чем реализуется)

### Passport model — 4 под-модели

| Под-модель | Вход | Метод | Статус |
|---|---|---|---|
| **Body** (форма/пропорция/масштаб) | обхваты/размеры (или CV pose) | **детерминированные правила** 5%/25% (Tier 1) | ✅ buildable now |
| **Color** (undertone/value/chroma/контраст→сезон+палитра) | фото → Lab кожи/волос/глаз | face-parsing → Lab → **правила** (Tier 1 признаки, Tier 2 ярлык) | 🟡 алгоритм now, нужен face-parsing dep |
| **Archetype** (эссенции-бленд, yin/yang) | онбординг (эстетики, «три слова») + опц. фото | правила + опц. LLM-оценка | ✅ buildable now (без фото) |
| **Taste** (SLOW-вектор: эстетики, бренды, бюджет) | онбординг + поведение | эмбеддинг, обучается на истории | 🟡 старт эвристикой, обучение — с данными |

### Rec model — 5 компонентов (из [STYLE_PASSPORT_AND_RECS.md §5](./STYLE_PASSPORT_AND_RECS.md))

| Компонент | Метод | Статус |
|---|---|---|
| **Hard filters** (context pre-filter + constraints) | правила: размер/наличие/бюджет/ограничения/погода/повод | ✅ now (логика), 🔴 данные каталога |
| **Retrieval** (мультимодальный) | FashionCLIP → ANN (pgvector) | 🔴 blocked on каталог |
| **Style-grammar rule-engine** (сезон/тело/эссенция → бусты атрибутов) | конфиг-правила (Tier 2, мягкие веса) | ✅ конфиг now |
| **Learned reranker + gated fusion** | CatBoost/DeepFM → SDM-style long/short | 🔴 нужны поведенческие данные |
| **LLM-сборка + заметка стилиста** | LLM (Gemini уже в стеке) | 🟡 нужен провайдер (B4), движок есть |

## 2. Что нужно (данные / инфра / модели / люди / решения)

### Данные
- 🔴 **Каталог с атрибутами и фото** (решение B1: WB/Ozon/Lamoda) — для эмбеддингов/ретривала. Главный разблокировщик.
- 🟡 **Gold eval-set** — 200–500 размеченных примеров `{запрос → хорошие/плохие товары}` + несколько десятков образов, размеченных стилистом. Это наша «правда» для offline-оценки (аналог 10 стилистов Daydream / human-in-the-loop Stitch Fix). Нужен **1 стилист на парт-тайм**.
- 🟢 **Онбординг → паспорт** — генерим сами (детерминированно). Поведенческие данные (клики/примерки/конверсии) появятся после запуска — до тех пор cold-start на content-based.

### Инфра
- 🟡 `pgvector` на Postgres (новая миграция `000011+`).
- 🟡 **Хост эмбеддинг-модели** (FashionCLIP, self-hosted; CPU хватает на батч-индексацию каталога, GPU — на масштаб).
- 🟡 **Python-сервис инференса** `mml-reco` (эмбеддинги, колориметрия, реранк, eval) — рядом с Go-ядром.
- 🟢 Feature store — сначала просто таблицы Postgres; выделенный — позже.
- 🟢 Weather API-ключ (контекст, фаза «Рост»).

### Модели
- **Эмбеддинги:** FashionCLIP (open, self-host) — решение ADR-1.
- **Колориметрия:** face-parsing (mediapipe / BiSeNet) → CIE Lab (2 оси: lightness+hue, не Fitzpatrick — против биаса) → правила сезона.
- **Body:** детерминированные правила (готово ниже).
- **Reranker:** старт — эвристический rule-engine; → learned (CatBoost/DeepFM) когда есть поведение.
- **LLM:** разбор намерения + заметка стилиста + обогащение каталога (через провайдер-абстракцию; Gemini уже подключён).

### Люди (минимум для этого трека)
- **1 ML/data-инженер (Python)** — эмбеддинги, retrieval, reranker, eval.
- **1 backend (Go)** — схема, сервисы, проводка (есть).
- **1 стилист парт-тайм** — gold-set, разметка, human-in-the-loop QA (страховка надёжности типологий).
- CTO (я) — архитектура/парность.

### Решения к фиксации (ADR)
- **ADR-1 Эмбеддинги:** FashionCLIP, dim (512/768), self-host.
- **ADR-2 Vector store:** pgvector сейчас → Qdrant при >5–10M векторов.
- **ADR-3 Граница сервиса:** Go-ядро ↔ Python-инференс (gRPC/HTTP), что где живёт.
- **ADR-4 Reranker:** когда переключаемся с эвристики на learned (порог по объёму конверсий).
- **ADR-5 Колориметрия:** какой face-parsing; 2-осевая модель тона кожи; аудит на тёмной коже.
- **ADR-6 Gold eval-set:** кто владеет, формат, объём, кадэнс обновления.

## 5. Оценка модели (Data Science ядро)

Рекомендации нельзя катить «на глаз». Слои оценки:

1. **Offline (до трафика):**
   - Retrieval: `recall@k`, `nDCG@k` на gold-set.
   - Соответствие правилам: `palette_match_rate`, `occasion_appropriateness`, `constraint_violation_rate` (должен быть 0 — жёсткие фильтры).
   - Cold-start sanity: паспорт без истории даёт осмысленную выдачу.
2. **LLM-judge + human-in-the-loop:** LLM-судья прогоняет выдачу по рубрике (уместность повода, палитра, силуэт), стилист выборочно ревьюит еженедельно — как Daydream. Это ловит то, что метрики не видят.
3. **Online (после запуска):** A/B на реранкере — первичная метрика **CR в примерку и в CPA-клик**, вторичные — save-rate, EPC. Рандомизация по пользователю, ≥1 бизнес-цикл, two-proportion z-test + доверительный интервал, guardrail (не роняем latency/served-rate). Poison-метрика: `constraint_violation_rate`.
4. **Bias-аудит:** качество колориметрии по тонам кожи (глубокие/тёплые/холодные) — обязательный отдельный прогон.
