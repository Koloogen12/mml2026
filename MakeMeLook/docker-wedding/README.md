# MML — локальный Docker-стек со свадебной коллекцией Christi

Полный MakeMeLook стек, запускаемый одной командой `docker compose up` на
локальной машине. В витрину `b2b.makemelook.ai/shop` загружены **139
свадебных платьев Christi Wedding** (Christi Couture, Berta, Dovita, Galia
Lahav), распарсенные через Tilda Store API.

## Что внутри

| Сервис        | Порт           | Что отдаёт                                                         |
|---------------|----------------|--------------------------------------------------------------------|
| `postgres`    | `5414`         | pgvector/pg16, пользователь `makemelook` / `makemelook`            |
| `minio`       | `9010` / `9011`| S3 + консоль, `minioadmin` / `minioadmin`                          |
| `minio-init`  | one-shot       | создаёт bucket `makemelook` + anonymous download policy            |
| `backend`     | internal       | Go API, автомиграции при старте, `/health` (НЕ опубликован наружу) |
| `edge`        | `3010`         | nginx-прокси перед backend: отдаёт `/s3/widget-assets/*` из фс     |
| `widget`      | `4173`         | `loader.js`, `widget.js`, `widget.css` (nginx + CORS `*`)          |
| `shop`        | `8080`         | Vite-бандл витрины (nginx, SPA, база `/shop/`)                     |
| `seed`        | one-shot       | `psql -f seeds/christi-wedding.sql` (профиль `seed`)               |

### Роль `edge`

`backend` не публикуется наружу. Весь HTTP-трафик в backend идёт через
`edge` (nginx) на `:3010`. Это позволяет:

1. **Раздавать виджетные картинки** (`intro-girl`, `mannequin-*`, `figure-type-*`
   и т.п.) прямо из `mml-saas-widget-tryon/src/assets/img/` по пути
   `/s3/widget-assets/*`, не заливая их в MinIO. В проде они лежат в bucket
   `widget-assets`, а nginx перед backend проксирует `/s3/*` в MinIO; у нас
   контент тот же, а путь — прямой `alias`.
2. **Поднять `client_max_body_size` до 50M** — иначе multipart upload
   пользовательской фотографии (5–20 МБ) бьётся об nginx default 1 MB.
3. Держать timeouts >5 минут для Gemini try-on запросов.

Конфиг — `edge/nginx.conf`.

Все артефакты, которые добавляются к исходному коду этим Docker-окружением,
живут рядом с кодом и **не ломают оригинальные dev-скрипты**:

```
docker-compose.local.yml        ← весь стек
edge/
  nginx.conf                    ← new (reverse-proxy перед backend)
mml-saas-backend/
  Dockerfile                    ← new
  docker-entrypoint.sh          ← new (ждёт postgres → migrate → server)
  .env.docker                   ← new (hostnames = имена docker-сервисов)
  .dockerignore                 ← new
mml-saas-widget-tryon/
  Dockerfile.static             ← new (build → nginx, не трогает dev Dockerfile)
  docker/nginx.conf             ← new
  .dockerignore                 ← new
demo-for-mml-main/
  Dockerfile                    ← new
  docker/nginx.conf             ← new
  .dockerignore                 ← new
scripts/
  generate-wedding-seed.mjs     ← new (CSV → SQL, включая widget_configs)
seeds/
  christi-wedding.sql           ← autogenerated, 139 products + 552 photos
```

## Первый запуск

```bash
cd /Users/danilkocnev/Desktop/MML/MakeMeLook/docker-wedding

# 1) сгенерировать seed SQL из CSV (один раз, no deps)
node scripts/generate-wedding-seed.mjs

# 2) собрать и поднять весь стек
docker compose -f docker-compose.local.yml up -d --build

# 3) когда backend станет healthy — прогнать seed
docker compose -f docker-compose.local.yml --profile seed run --rm seed
```

После этого:

- Витрина: <http://localhost:8080/shop>
- Storefront API: <http://localhost:3010/api/storefront/v1/11111111-1111-1111-1111-111111111111/products>
- MinIO console: <http://localhost:9011> (`minioadmin` / `minioadmin`)

## Фикс-нюанс с колонкой color

`storefront_repo.go#GetFiltersAgg` читает `SELECT DISTINCT color` в `[]string`
и не умеет в NULL — поэтому свадебные платья, у которых Christi не указывает
цвет, в seed-скрипте получают `color = 'off-white'` по умолчанию (это
типичный bridal-цвет и разумный фолбэк). Генератор в
`scripts/generate-wedding-seed.mjs` это учитывает.

Если появятся товары с реальными цветами в CSV — они используются как есть.

## Перезапуск после изменений в коде

Любое изменение в исходниках backend/widget/shop — перебилд образа:

```bash
docker compose -f docker-compose.local.yml up -d --build backend
docker compose -f docker-compose.local.yml up -d --build shop widget
```

## Перезалить товары (seed идемпотентный)

```bash
# если поменяли CSV или генератор:
node scripts/generate-wedding-seed.mjs

# перелить (скрипт DELETE'ает существующие товары проекта и вставляет заново)
docker compose -f docker-compose.local.yml --profile seed run --rm seed
```

## Полный снос стенда

```bash
docker compose -f docker-compose.local.yml down -v
```

(`-v` удаляет volume'ы postgres и minio, следующий запуск будет с нуля.)

## Env vars, которые стоит знать

Всё вшито в `mml-saas-backend/.env.docker` — он копируется в образ как
`/app/.env` и читается `godotenv.Load()` при старте сервера.

Ключевые:

| var                      | значение                                       |
|--------------------------|------------------------------------------------|
| `DB_HOST`                | `postgres` (docker service name)               |
| `MINIO_ENDPOINT`         | `minio:9000`                                   |
| `MINIO_PUBLIC_URL`       | `http://localhost:9010` (видно из браузера)    |
| `WIDGET_CDN_URL`         | `http://localhost:4173/widget`                 |
| `CORS_ALLOWED_ORIGINS`   | `localhost:8080,4173,5173,5174`                |
| `GEMINI_API_KEY`         | тот же ключ, что был в оригинальном `.env`     |

Хочешь другой Gemini ключ — не пересобирая образ:

```bash
docker compose -f docker-compose.local.yml run --rm \
  -e GEMINI_API_KEY=AIzaXXX... \
  backend
```

(или через блок `environment:` в `docker-compose.local.yml`)

## Что можно демонстрировать

1. Открываешь <http://localhost:8080/shop> — видно 139 свадебных платьев,
   фильтры по бренду (Berta / Christi Couture / Dovita / Galia Lahav),
   цены 175K – 1.4M ₽.
2. Кликаешь карточку — загружается страница платья + виджет примерки
   (подтягивается с `localhost:4173/widget/loader.js`).
3. Виджет открывает сессию через `localhost:3010/api/v1/widgets/...`, грузит
   аватары и запускает try-on.
4. Gemini API вызывается с валидным ключом из `.env.docker` — реальная
   виртуальная примерка работает.
