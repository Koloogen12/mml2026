# SEO-основа лендинга MakeMeLook

Документ описывает, как устроена индексация лендинга `b2b.makemelook.ai`, какие
решения приняты и почему, и что осталось подключить руками в файлах страниц.

Код лежит в `src/seo/` (`site.ts`, `metadata.ts`, `jsonld.ts`), маршруты —
`src/app/robots.ts` и `src/app/sitemap.ts`, обложка — `public/landing/ru/og-ru-landing.jpg`
(генератор `scripts/og-image.mjs`).

---

## 1. Адреса и канонические ссылки

**Боевой адрес один: `https://b2b.makemelook.ai`.** Он прибит константой в
`src/seo/site.ts` (переопределяется переменной `SITE_URL`), а не берётся из
заголовка запроса. Причины две:

1. На сервере рядом живут соседние проекты. То же приложение может открыться
   по чужому имени или по IP — и если канонический адрес собирать от текущего
   хоста, у каждой такой двери появится собственная копия страницы. Абсолютный
   канонический адрес схлопывает их в одну.
2. В `Dockerfile` `ARG BASE_URL` по умолчанию `https://makemelook.ai` — это
   ДРУГОЙ продукт (платформа для покупателей). Метаданные лендинга не должны
   на него ссылаться ни при каких обстоятельствах.

Все канонические ссылки, `og:url`, `sitemap` и JSON-LD собираются абсолютными от
этой константы. Это же закрывает дубли по UTM-меткам: `?utm_source=...` ведёт на
страницу, которая сама указывает на адрес без параметров.

Маршруты живут в одном месте — `routes` в `src/seo/site.ts`:

```
landing:      '/'
blog:         '/blog'
blogArticle:  '/blog/<slug>'
```

Если маршруты снова поменяются, правятся только эти три строки.

## 2. hreflang — решение: не ставить

Короткий ответ: **hreflang сейчас не нужен и был бы вреден.**

`hreflang` описывает страницы, которые являются одним и тем же контентом на
разных языках. На сайте формально есть англоязычные страницы (`/en`,
`/en/platform`), но это не перевод нового лендинга: это старый лендинг с другой
структурой, другим оффером и другим набором блоков. Связать их через `hreflang`
значит сказать поисковику «вот это — английская версия вот этого», что неправда.
За это не наказывают напрямую, но поисковик перестаёт доверять кластеру и может
показывать в русской выдаче английскую страницу.

Что делаем вместо:

- `og:locale = ru_RU`, `inLanguage = ru-RU` в JSON-LD (уже в коде);
- `<html lang="ru">` — **требует правки корневого layout, см. §10**;
- самоссылающийся canonical на каждой странице.

**Когда включать hreflang:** если появится настоящая англоязычная версия того же
лендинга (те же блоки, тот же оффер). Тогда достаточно добавить в
`landingMetadata.alternates.languages` пару `ru-RU` / `en` и `x-default`. Раньше —
не нужно.

## 3. robots.txt

Отдаётся кодом (`src/app/robots.ts`), а не файлом в `public/`, чтобы адрес
sitemap и список закрытых разделов брались оттуда же, откуда канонические ссылки.
Рассинхрон robots.txt и sitemap.xml — самая частая причина «страница закрыта в
robots.txt» в панели вебмастера.

Открыто: `/` (лендинг), `/blog`, `/blog/*`, статика лендинга.

Закрыто:

| Путь | Почему |
|---|---|
| `/admin` | кабинет редактора блога и лидов |
| `/api` | служебные ручки, отдают JSON |
| `/ai-agent` | внутренняя страница |
| `/widget-test` | тестовый стенд виджета |
| `/shop` | демо-витрина, не наш коммерческий контент |
| `/widget`, `/widgetfit` | статика виджета |

Директива `Host` указана явно — тем же соображением про соседей по серверу.
`Clean-param` для UTM не ставим: формат `robots.ts` в Next такую строку не умеет,
а дубли по меткам уже закрыты каноническим адресом.

## 4. sitemap.xml

`src/app/sitemap.ts`, `force-dynamic`.

- **Лендинг** — `priority 1.0`, `changefreq weekly`, `lastmod` из константы
  `LANDING_LAST_MODIFIED`. Специально константа, а не `new Date()`: если в
  sitemap каждый раз подставлять текущее время, поисковик быстро перестаёт
  верить полю. Правило: правим тексты или блоки лендинга — двигаем дату в том же
  коммите.
- **Список журнала** — `0.7`, `weekly`, `lastmod` = дата самой свежей статьи.
- **Статьи** — `0.6`, `monthly`, `lastmod` = `updated ?? date`.

Список статей берётся тем же `getMergedArticles()`, что и сами страницы журнала
(опубликованные из базы плюс статические, которые база ещё не перекрыла). Иначе
sitemap показывал бы не то, что реально открывается. Если база недоступна,
sitemap не падает целиком, а отдаёт статический набор — потерять из-за этого
лендинг было бы дороже.

**Что стоит улучшить:** `getMergedArticles()` выбрасывает `updatedAt` из базы
(`toArticle()` в `src/data/blog-db.ts` ставит `updated: undefined`). Из-за этого
`lastmod` статьи из базы равен дате публикации, даже если статью правили. Правка
на одну строку — `updated: p.updatedAt.toISOString().slice(0, 10)`, — но файл
сейчас в работе у переезда маршрутов, поэтому вынесен сюда, а не сделан.

## 5. Структурированные данные

Принцип: размечаем только то, что реально есть на странице.

### Что размечено

| Тип | Где | Чем подтверждается на странице |
|---|---|---|
| `Organization` | лендинг, журнал, статья | футер: MakeMeLook, ООО «МОНОРУС», hello@makemelook.ai, Москва |
| `WebSite` | лендинг | сам сайт |
| `SoftwareApplication` | лендинг | продукт — виджет; цена 8 ₽ напечатана в блоке «Арифметика возвратов» |
| `FAQPage` | лендинг | блок «Что обычно спрашивают», 8 вопросов один в один |
| `BreadcrumbList` | журнал, статья | путь Главная → Журнал → Статья |
| `BlogPosting` | статья | сама статья, автор и даты |

### Чего сознательно нет

- **`AggregateRating` / `Review`** — отзывов и оценок на сайте нет. Разметить их
  значило бы показать в выдаче звёзды, за которыми ничего не стоит; это прямое
  нарушение правил и повод для ручных санкций.
- **`SearchAction` у `WebSite`** — поиск в журнале работает на клиенте и не
  открывается ссылкой вида `?q=...`. Разметка обещала бы поисковику страницу
  результатов, которой нет.
- **`LocalBusiness`** — это SaaS. `LocalBusiness` у поисковиков означает точку
  обслуживания, куда приходят клиенты; юридический адрес такой точкой не является.
- **`geo` (координаты)** — проверенных координат у нас нет, а выдуманные — это
  разметка под то, чего нет. См. §11, открытый вопрос про Яндекс Бизнес.

`FAQPage` остаётся в `src/app/(landing)/jsonld.generated.json` и передаётся в
`landingGraph()` снаружи: вопросы генерируются из макета, и дублировать их в
`src/seo/` значило бы развести разметку и видимый текст.

## 7. Заголовочная структура

### Как сейчас

Один `<h1>` — правильно. Скачков уровней нет. Основная проблема в другом:
часть визуальных заголовков размечена как `div`/`span`, поэтому робот не видит
структуру там, где человек её видит.

| # | Блок | Сейчас | Что менять |
|---|---|---|---|
| 01 | Hero | надзаголовок `div`, **H1 «Ваша одежда на покупателе до заказа»** | ничего |
| 01b | Compat («Работает на») | заголовка нет, полоса логотипов | заголовок не нужен; добавить `aria-label="Платформы, на которых работает виджет"` на `<section>` |
| 01c | Bridge | `<p>` кеглем 28–50px: «Каталог показывает вещь. Покупателю нужно увидеть в ней себя» | **сделать `<h2>`** — по смыслу и по кеглю это заголовок раздела |
| 02 | Steps | H2 + 3×H3 | ничего |
| 03 | Guess | H2 «Где здесь съёмка, а где примерка?» | ничего |
| 04 | Situations | H2 «Найдите свою» + 3×H3 | H2 не самодостаточен; см. приём с `<span>` ниже |
| 05 | Calc | H2 «Сколько стоит чужая неуверенность» | ничего |
| 06 | WhyWorks | H2 + H3 «Это точно ваш артикул…» | заголовки колонок сравнения (`MAKEMELOOK`, `ПРИМЕРКА У МАРКЕТПЛЕЙСОВ`, …) — `div`; желательно, но не обязательно, перевести блок в `<table>` с `<th>` |
| 07 | WhyNow | H2 «Примерка переехала в логистику» | ничего |
| 08 | Product | H2 «Инструменты, которые работают на вас» | ничего; вкладки — кнопки, это верно |
| 09 | Connect | H2 + H3 «Что нужно от вашей команды»; 5 шагов подключения — `<span>` | **названия 5 шагов → `<h3>`** |
| 10 | Data | H2; 4 пункта («Данные остаются вашими» и т.д.) — `<span>` | **4 заголовка пунктов → `<h3>`** |
| 11 | Alternatives | H2 «Почему мы, а не»; 5 возражений — `<div>` | **5 возражений → `<h3>`**; H2 не самодостаточен, см. ниже |
| 12 | Journal | H2 + H3 главной статьи; 3 карточки — `<span>` | **3 заголовка карточек → `<h3>`** |
| 13 | Faq | H2; 8 вопросов — `<div>` | **8 вопросов → `<h3>`** — это же связывает видимый текст с разметкой `FAQPage` |
| 14 | Cta | H2 «Посмотрите на своих товарах» | ничего |
| 15 | Footer | заголовков нет | ничего; `ПРОДУКТ / ИНТЕГРАЦИИ / КОМПАНИЯ` — навигация, заголовками быть не обязаны |

### Приём с `<span>` для блоков 04 и 11

`<h2>Найдите свою</h2>` и `<h2>Почему мы, а не</h2>` вне контекста не значат
ничего: смысл несёт надзаголовок, который лежит отдельным `div` выше. Вместо
переписывания копирайта предлагается втянуть надзаголовок внутрь `h2` — видимый
текст и вёрстка не меняются, меняется только вложенность:

```jsx
<h2>
  <span style={{ /* стили нынешнего надзаголовка, display: 'block' */ }}>Три ситуации</span>
  Найдите свою
</h2>
```

То же для блока 11: `Альтернативы` + `Почему мы, а не`.

### Итог после правок

Ровно один H1; H2 на каждый смысловой раздел; H3 на карточки, шаги, пункты и
вопросы внутри разделов. Скачков уровней нет.

## 8. title, description, семантика

### Кто ищет

Покупатель — владелец или маркетолог интернет-магазина одежды в России. Он ищет
не «AI», а решение задачи: как показать вещь на покупателе и перестать платить
за возвраты. Отсюда профиль запросов:

- **головные:** виртуальная примерка одежды, виртуальная примерочная для сайта,
  виджет примерки для интернет-магазина;
- **по механике:** примерка одежды по фото, подбор размера онлайн, рекомендация
  размера в интернет-магазине;
- **по боли:** как снизить возвраты одежды, возвраты в интернет-магазине одежды;
- **по платформе:** примерка для Tilda, примерка для InSales, примерочная
  1С-Битрикс.

Головной запрос вынесен в начало title, потому что бренд пока никто не ищет —
по «MakeMeLook» трафика нет, и ставить его первым значит тратить самые заметные
символы выдачи на слово, которое ничего не значит для читателя.

### Лендинг

**title** (62 символа):
```
Виртуальная примерка одежды для интернет-магазина — MakeMeLook
```

**description** (198 символов):
```
Виджет примерки на сайт магазина одежды: покупатель загружает одно фото и видит вашу вещь на себе, до пяти слоёв в образе. Размер считается по вашей размерной сетке. Скрипт ставится за десять минут.
```

Описание собрано из первого экрана и блоков 02/06/09 — то есть обещает ровно то,
что человек увидит, перейдя. Три конкретики (одно фото, пять слоёв, размерная
сетка) отличают сниппет от конкурентов, у которых в описании «AI-примерочная для
вашего бизнеса».

### Журнал

**title:** `Журнал MakeMeLook — возвраты, размерные сетки и примерка`

**description:** `Разборы на данных магазинов одежды: из чего складывается цена возврата, как собрать размерную сетку и какие фото товара подходят для примерки. С методикой и источниками.`

### Статья

`«<Заголовок статьи>» — Журнал MakeMeLook`, description — `excerpt` статьи.

### Ключевые слова

`meta keywords` заполнен (`KEYWORDS` в `src/seo/metadata.ts`), но без иллюзий:
Google игнорирует поле с 2009 года, Яндекс — с середины десятых. Оставлено как
справка для команды о том, под какие запросы писался текст. Настоящая семантика
живёт в H1, подзаголовках и тексте блоков, и там она уже есть: «виртуальная
примерка», «интернет-магазин одежды», «размерная сетка», «возвраты», названия
платформ. Дополнительное насыщение текста ключами не требуется и делать его не
надо.

## 9. alt-тексты

Картинки лендинга уже подписаны осмысленно — проверены все 30. Два замечания:

1. `S08Product.tsx:209`, `/landing/ru/look-1.jpg` — `alt=""` без
   `aria-hidden="true"`. Если картинка декоративная, добавить `aria-hidden`;
   если содержательная — подписать.
2. Видео первого экрана (`HeroMedia`) для робота немое. Постер
   `hero-poster-16x9.webp` задаётся фоном, альтернативного текста у блока нет.
   Смысл первого экрана несёт H1, так что критичного ничего, но `aria-label` на

Эталон подписи, которым пользоваться дальше: не «фото платья», а что именно
видно и зачем — «Один человек в одной позе, 4 слоя одежды: те же три вещи плюс
трикотажный жилет».

## 10. Найденные дефекты (не правил — чужие файлы)

1. **`<html lang="en">` в `src/app/layout.tsx`.** Лендинг русскоязычный, и
   теперь он лежит на корне. Атрибут надо поменять на `ru` (либо задать `lang`
   через сегментный layout). Сейчас это прямой сигнал поисковику, что страница
   английская.
2. **Метаданные страницы лендинга устарели.** В `src/app/(landing)/page.tsx`
   `canonical` и `og:url` всё ещё `/ru/v2`, а `og:image` — заглушка
   `/assets/images/og-ru.jpeg`. Готовая замена — в §12.
3. **Нет редиректов со старых адресов.** `/ru`, `/ru/v2`, `/ru/blog/*` после
   переезда отдают 404. Нужны 301 на `/`, `/`, `/blog/*` соответственно
   (`redirects()` в `next.config.mjs`).
4. **Битые ссылки на лендинге.** В блоке «Журнал» четыре ссылки ведут на
   `./MakeMeLook Article.dc.html` — файл из макета, которого на сайте нет.
   Ссылка «Читать полностью →» в блоке 07 ведёт на
   `/blog/primerka-pereehala-v-logistiku` — такой статьи нет ни в базе, ни в
   статическом наборе. Ещё пять ссылок в футере — заглушки `href="#"`.
5. **Список журнала ниоткуда не доступен.** На лендинге нет ни одной ссылки на
   `/blog`: в футере «Журнал» ведёт на якорь `#journal`. Раздел висит сиротой —
   робот найдёт его только через sitemap, вес с лендинга на него не течёт.
   Нужна обычная ссылка на `/blog`.
6. **Демо-контент в журнале.** Из восьми статей две лежат в базе, шесть — это
   посевные материалы из макета, с выдуманными авторами (Алина Соколова, Игорь
   Лавров и т.д.) и выдуманными кейсами. Сейчас они открываются и попадают в
   sitemap. Индексировать выдуманные кейсы за подписью несуществующих людей —
   риск, и не поисковый, а репутационный. Решение за владельцем, см. §11.

## 11. Открытые вопросы к владельцу

1. **Демо-статьи журнала.** Убрать посевные шесть статей, заменить настоящими
   или оставить как есть? Пока они в индексе, журнал работает против доверия к
   продукту, а не на него.
2. **Яндекс Бизнес / регион в Вебмастере.** Есть ли карточка организации? Если
   да — дайте ссылку, добавлю `sameAs` и координаты из карточки (не выдуманные).
   Если нет — регион задаётся в Яндекс Вебмастере вручную, это разовое действие
   в кабинете.
3. **Соцсети для `sameAs`.** В футере есть слово «Telegram», но ссылки нет
   (`href="#"`). Нужны реальные адреса Telegram-канала и других профилей —
   `sameAs` заметно помогает поисковику слепить сущность компании.
4. **Коды подтверждения прав** для Яндекс Вебмастера и Google Search Console.
   Как только дадите — вставлю в `verification` метаданных.
5. **Страницы `/ru/platform` и `/en/*`.** Остаются в индексе как есть или
   закрываем? Это материалы про другой продукт, на том же хосте они растворяют
   тематику лендинга.
6. **`LANDING_LAST_MODIFIED`.** Договоримся двигать дату в коммите, который
   меняет тексты лендинга, — иначе поле протухнет.

## 12. Что подключить (готовые куски)

Метаданные конкретных страниц специально не вписаны — файлы были в работе у
переезда маршрутов. Всё готово к вставке.

### `src/app/(landing)/page.tsx`

```tsx
import { landingMetadata } from '@/seo/metadata';
import { landingGraph } from '@/seo/jsonld';
import faqJsonLd from './jsonld.generated.json';

export const metadata = landingMetadata;

export default function LandingPage() {
  return (
    <>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(landingGraph(faqJsonLd)) }}
      />
      <Landing />
    </>
  );
}
```

Старый блок `export const metadata` и отдельный `<script>` с одним только FAQ
удаляются: `landingGraph()` кладёт FAQ в тот же граф вместе с `Organization`,
`WebSite` и `SoftwareApplication`.

import { blogIndexMetadata } from '@/seo/metadata';

### `src/app/blog/[slug]/page.tsx`

```tsx
import { blogArticleMetadata } from '@/seo/metadata';
import { blogArticleGraph } from '@/seo/jsonld';

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const article = await getMergedArticleBySlug(params.slug);
  if (!article) return { title: 'Статья не найдена — MakeMeLook', robots: { index: false } };
  return blogArticleMetadata({
    slug: article.slug,
    title: article.title,
    excerpt: article.excerpt,
    lead: article.lead,
    cover: article.cover,
    date: article.date,
    updated: article.updated,
    authorName: authors[article.authorId]?.name
  });
}
```

И в разметке страницы — `<script type="application/ld+json">` с
`blogArticleGraph({...})` теми же полями.

### Служебные страницы

Для `/admin`, `/widget-test`, `/shop` и `/ai-agent` есть
`noindexMetadata('Заголовок')` — закрытие в robots.txt не мешает странице попасть
в индекс по внешней ссылке, мета-тег `noindex` мешает.

## 13. Обложка для соцсетей

`public/landing/ru/og-ru-landing.jpg`, 1200×630, ~100 кБ. Собрана из кадра
первого экрана (`hero-16x9.mp4`, 5-я секунда) — чтобы превью в мессенджере и
первый экран сайта показывали одно и то же. На кадре образ из пяти слоёв и
панель виджета: это и есть то, что продаёт продукт. Поверх — те же два
градиента, что лежат на hero, и текст первого экрана.

Пересобрать после смены hero: `node scripts/og-image.mjs` (нужны `ffmpeg` и
шрифты Unbounded и Golos UI в системе; результат коммитится, в Docker-сборке
скрипт не участвует).

`twitter:card` — `summary_large_image`, та же картинка.
